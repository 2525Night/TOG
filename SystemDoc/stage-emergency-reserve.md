## 1. מטרת השלב במערכת

אחרי שיש תזרים מובן ושליטה בסיסית בהתחייבויות, המערכת מלווה את המשתמש לבניית **רזרבה להפתעות** — סכום מופרד מהשוטף שנועד למנוע חזרה למינוס או לחוב כשמשהו נשבר (רכב, רפואה, תיקון דחוף).

זה **שלב ביניים** במסלול:

```
שליטה בתזרים / התחייבויות
        ↓
רזרבה להפתעות   ← המסמך הזה
        ↓
יעדים וחיסכון / צמיחה
```

לא תקציב אחוזים מהשכר. לא מעטפות מלאות. לא השקעות.

---

## 2. הגדרת הרעיון בשלמותו

### 2.1 מה זה

| | |
|---|---|
| **שם למשתמש** | רזרבה להפתעות *(שם פנימי / kind: `EMERGENCY` — אפשר להשאיר «כרית ביטחון» כשם יעד ברירת מחדל)* |
| **סוג** | יעד ייחודי אחד למשתמש (`kind = EMERGENCY`) |
| **מהות** | סכום־מטרה + התקדמות מהקצאות מהפנוי (כמו יעד רגיל) |
| **לא מהות** | חשבון בנק נפרד, אחוז קבוע מהשכר, נעילת כסף במערכת |

### 2.2 משפט מוצר אחד

> «סכום שמפרידים מהשוטף כדי לא לחזור למינוס כשמשהו נשבר.»

### 2.3 מה זה *לא*

- לא «חיסכון לכל דבר» / חופשה / רכב חדש → אלה יעדים רגילים (`GENERAL`)
- לא חובה למשתמש ב־Recovery כבד (מינוס חריף, חובות קריטיים בלי נותר)
- לא מערכת אחוזים (50/30/20) — זה שלב מוצר נפרד, מאוחר יותר אם בכלל
- לא כפל ספירה מול MonthFacts: הקצאה ליעד ממשיכה כמו היום (`goal_funding`)

### 2.4 מתי השלב «פעיל» למשתמש

המערכת **מציעה / מדגישה** רזרבה כשמתקיים לפחות אחד:

1. יש **נותר חיובי** בחודש (או ממוצע חודשים אחרונים), **ו־**
2. אין מינוס עו״ש חריף / התראת Recovery דומיננטית, **ו־**
3. עדיין אין יעד `EMERGENCY`, או שיש והוא מתחת ליעד

אם התנאים לא מתקיימים: **לא CTA בולט** — רק אפשרות שקטה ב«יעד חדש» («זה רזרבה להפתעות?»).

### 2.5 איך נקבע סכום המטרה

לא יצירה עיוורת בלחיצה.

| מקור | כלל מוצע (ברירת מחדל) |
|---|---|
| יש נותר חודשי | `max(3,000, round(נותר × 3))` — כ־3 חודשי «רווח» קטן, עם רצפה |
| אין נותר | הצעה `3,000`–`5,000` עם הסבר «התחלה קטנה» |
| משתמש | **תמיד** יכול לשנות לפני יצירה ואחר כך בעריכה |

הסבר קצר ליד הסכום: «הצעה להתחלה — אפשר לשנות. מטרה נפוצה בהמשך: כ־1–3 חודשי הוצאות קבועות.»

### 2.6 מה עושים עם כסף שנשאר (נותר)

ללא שינוי ארכיטקטורה — רק בהירות:

1. **קודם** — עמידה בהתחייבויות ידועות (הלוואות / חיוב כרטיס)  
2. **אחר כך** — אם רזרבה לא מלאה: עידוד הקצאה לרזרבה מהפנוי  
3. **אחר כך** — יעדים אחרים / השארת בעו״ש / חופש מודע  

«מה שנשאר» = `פנוי להקצאה` הקיים. הרזרבה היא **יעד מועדף**, לא מעטפת אחוזים.

### 2.7 הבדל מיעד רגיל (UX)

| | רזרבה | יעד רגיל |
|---|---|---|
| כמות | לכל היותר אחת | רבים |
| שפה | הגנה / הפתעות | חלום / קנייה / תאריך |
| מיקום | ראשון ברשימה כשקיים; CTA רק כשרלוונטי | אחריה |
| פעולה ראשית | «הקצה לרזרבה» | «הקצה מהפנוי» |
| אחרי מילוי | «הרזרבה מלאה — אפשר ליעדים אחרים» | הושלם |

### 2.8 תמונת מצב

כשיש רזרבה:

- שורה קצרה: «רזרבה להפתעות · X מתוך Y» או «הרזרבה מלאה»
- קישור ליעדים
- בלי פס בלבד בלי משמעות

כשאין ורלוונטי: קישור שקט «להתחיל רזרבה» — לא חסימת מסך.

### 2.9 גבולות שלב זה (מחוץ לסקופ)

- תקציב אחוזים / תקרות סל שוטפות  
- נעילת כסף / חשבון נפרד / Open Banking לרזרבה  
- משיכה מרזרבה כסוג תנועה מיוחד (יכול להיות בהמשך)  
- המרת אוטומטית של תשלום חוב שנסגר לרזרבה (חזון מהקונספט — שלב נפרד)

## 3. קריטריוני הצלחה

1. משתמש חדש מבין תוך ~5 שניות **למה** הרזרבה קיימת (משפט אחד + סכום).  
2. אין יצירת יעד `EMERGENCY` בלי אישור סכום.  
3. ב־Recovery בלי נותר — אין לחץ CTA.  
4. הקצאה לרזרבה = אותה מכונה כמו יעדים (pool / MonthFacts נשארים עקביים).  
5. אחרי מילוי — המסר עובר ליעדים / פנוי, לא נשאר «דחוף».

## 5. סדר ביצוע מומלץ

```
A (שפה) → B (אשף סכום) → D (תמונת מצב) → C (תנאי הצגה) → E (מסלול)
```

C אחרי D אם רוצים ערך למשתמש מהר; C לפני D אם חשוב קודם לא להציק ב־Recovery.

**ברירת מחדל מומלצת:** A → B → D → C → E.
