# תוכנית: משוב, התראות ומרכז פעילות

**שם הקובץ:** `notifications-feedback-plan.md`  
**מיקום:** `SystemDoc/notifications-feedback-plan.md`  
**סטטוס:** טיוטת עבודה לקראת סיום פיתוח (טרם משתמשים חיים)  
**תאריך עדכון:** 2026-09-11  
**בסיס:** ביקורת באנרים/התראות + החלטת סדר מעודכנת + החלטת מוצר: התראות נשארות (read/unread) + ערוץ מערכת אנדרואיד  
**ויזואליזציה לטלפון:** [`Designs_Ideas/Notifications-Center/index.html`](../Designs_Ideas/Notifications-Center/index.html)

## 1. הקשר והחלטה

### מצב היום
- אין toast גלובלי; משוב = באנרים inline דביקים (`form-error` / `form-success` / `badge good`) לפי עמוד.
- ברועי באנר הצלחה מעל הצ׳אט חוסם תוכן (נצפה באימולטור).
- אין מרכז התראות / יומן פעולות אחד.
- `notificationMode` משפיע בעיקר על nudges בתוך רועי.
- אפליקציית אנדרואיד = Capacitor WebView ל־web; **אין** כרגע plugin של Local/Push Notifications (`apps/mobile` כולל בעיקר App, Preferences, StatusBar).
- המערכת בשלבי פיתוח לקראת סיום — **אין משתמשים חיים**.

### החלטות מוצר (מעודכנות)
1. **סדר בנייה:** סכמה → Toast באפליקציה → מרכז שירות → (אופציונלי/המשך) התראות מערכת באנדרואיד.  
   לא מתחילים ממרכז או מ־OS לבדם.
2. **התראות במרכז לא נעלמות** — עוברות `unread` → `read`; נשארות עד מחיקה/ניקוי ידני מההגדרות.
3. **Toast באפליקציה** כן נעלם אחרי ~2–3 שנ׳ (משוב מיידי בלבד); הרשומה במרכז נשארת לפי הכללים.
4. **ערוץ אנדרואיד (מגש המערכת)** נכנס לתוכנית במפורש — עם שליטה מלאה מלשונית **הגדרות** במרכז השירות: מה מותר להגיע לטלפון, ומה נשאר רק בתוך האפליקציה.

## 2. מטרות

1. משוב מיידי שלא חוסם תוכן (במיוחד צ׳אט רועי) — Toast.
2. מודל נתונים אחיד לכל סוגי ההתראות/הפעולות — סכמה אחת לכל הערוצים.
3. מקום אחד (מרכז שירות) עם ניווט ברור: **התראות / עדכונים / הגדרות**.
4. הבחנה ויזואלית ברורה בין **חדש** ל־**נקרא**; בלי היעלמות אוטומטית של פריטי מרכז.
5. אפשרות להתראה גם **במערכת אנדרואיד** (כשהאפליקציה ברקע / סגורה חלקית), תחת שליטת המשתמש בהגדרות.
6. מוכנים להשקה בלי באנרים דביקים כדפוס ברירת מחדל.

### Out of scope (גלים מוקדמים)
- SMS / אימייל שיווקי.
- התראות iOS (אלא אם יתווסף יעד בהמשך; התכנון הטכני דומה אבל המימוש הנוכחי הוא Android-first).
- שיכתוב מלא של מנוע nudges למוצר נפרד.
- **Push מלא מול FCM בפרודקשן** — מתוכנן כתת־שלב אחרי Local; לא חוסם השקה אם Local מוכן.

### In scope במפורש (חדש)
- Capacitor **Local Notifications** לאנדרואיד.
- העדפות משתמש: אילו `kind` / מקורות מורשים לערוץ `OS`.
- הרשאות אנדרואיד 13+ (`POST_NOTIFICATIONS`), ערוצי Notification Channel, deep link בחזרה לאפליקציה.
- אופציה עתידית ל־**Push (FCM)** על אותה סכמה ואותן הגדרות.

## 3. מפת ערוצים (איפה מה מופיע)

| ערוץ | איפה המשתמש רואה | נעלם לבד? | נשלט מ… |
|------|-------------------|-----------|----------|
| `TOAST` | בתוך האפליקציה, מעל ה־dock | כן (~2–3 שנ׳) | הגדרות → «Toast מיידי במסך» |
| `CENTER` | מרכז שירות (התראות / עדכונים) | **לא** — רק read/unread + מחיקה | הגדרות → «מה נשמר כאן» |
| `OS` (Android) | מגש התראות של הטלפון / ראש מסך | לפי מערכת / dismiss משתמש | הגדרות → «התראת מערכת באנדרואיד» + פירוט סוגים |
| `BOTH` / שילובים | למשל Toast+Center, או Center+OS | לפי כל ערוץ בנפרד | מטריצת העדפות (סעיף 5) |

**עקרון:** אירוע אחד בסכמה יכול להפיץ ל־0..N ערוצים אחרי סינון העדפות המשתמש. אין כפילות לוגית — יש `delivery` לכל ערוץ.

## 4. תוכנית בשלבים

### שלב A — סכמת התראות (דקה, כולל מוכנות ל־OS)

**מה בונים**
- מודל משותף (`packages/shared` + טבלת API אם נשמר בשרת), למשל:

```text
NotificationEvent {
  id, createdAt, userId
  kind: SUCCESS | ERROR | INFO | IMPORTANT | NUDGE
  source: MONEY | CASH | ROEY | DEBTS | GOALS | SETTINGS | SYSTEM
  titleHe, bodyHe
  entityType?, entityId?, actionUrl?          // deep link פנימי, למשל /app/roey
  readAt?                                     // null = חדש/לא נקרא במרכז
  archivedAt? / deletedAt?                    // מחיקה רכה אופציונלית
  ttlSeconds?                                 // ל־TOAST בלבד
  deliveries: {
    toast?: { shownAt?, dismissedAt? }
    center?: { tab: ALERTS | UPDATES }
    os?: { enabledByPolicy, requestedAt?, deliveredAt?, notificationId?, channelId? }
  }
}
```

- **מיפוי ללשוניות מרכז (לא נעלם):**
  - לשונית **התראות:** `IMPORTANT` | `NUDGE` | `ERROR` (כשדורש טיפול) → תמיד נשמרים; `readAt` מסמן נקרא.
  - לשונית **עדכונים:** `SUCCESS` | `INFO` → יומן «מה נעשה»; גם כאן נשמרים; אופציונלי read/unread.
- **שדות מדיניות ל־OS** (על האירוע או על כלל גלובלי):
  - `osEligible: boolean` — האם *מותר בכלל* לשלוח למערכת (ברירת מחדל: רק IMPORTANT/NUDGE; לא SUCCESS שגרתי).
  - אחרי סינון העדפות המשתמש → `deliveries.os`.

**כללי סיווג ראשוניים**
| אירוע | Toast | מרכז | OS (ברירת מחדל מומלצת) |
|--------|-------|------|-------------------------|
| הצלחת פעולה (שמירת הוצאה, סשן חדש) | כן | עדכונים | **לא** (רועש מדי) |
| שגיאת API רגילה בזמן שימוש | כן | אופציונלי | לא |
| שגיאה שדורשת טיפול מאוחר (ייבוא נכשל) | כן | התראות | אופציונלי (כבוי כברירת מחדל) |
| סיכון / חשוב מרועי | כן (קצר) | התראות | **כן** אם המשתמש אישר OS |
| Nudge רועי | לפי mode | התראות | **כן** אם mode מאפשר + OS דלוק |
| סיכום שבועי | לא חובה | עדכונים / התראות | כן (מתוזמן Local) |

**Done when**
- טיפוסים + תיעוד חוזה שמירה (DB מול ephemeral).
- לפחות producer אחד מייצר אובייקט סכמה מלא כולל `osEligible`.

### שלב B — ערוץ מיידי (Toast באפליקציה)

**מה בונים**
- `ToastProvider` גלובלי מעל dock + safe-area.
- `notify(event)` לפי סכמה; auto-dismiss לפי `ttlSeconds`; × לסגירה.
- מיגרציה מבאנרים דביקים: רועי P0 → כסף/מזומן → יעדים/חובות/הגדרות.
- **חשוב:** Toast שנעלם **לא** מוחק את רשומת המרכז.

**Done when**
- רועי בלי באנר דביק על הצ׳אט; toast בתחתית.
- 3+ מסכי ליבה על toast.
- בדיקת אימולטור/דפדפן מקומי.

### שלב C — מרכז שירות (התראות / עדכונים / הגדרות)

**מבנה ניווט (IA)**
- **התראות** — דורש תשומת לב; תגיות «חדש» / «נקרא»; CTA; **לא נעלמות**.
- **עדכונים** — יומן הצלחות לפי יום.
- **הגדרות** — עוצמה + מה נשמר + Toast + **בלוק מפורט להתראות אנדרואיד** (סעיף 5).

ויזואל: `Designs_Ideas/Notifications-Center` §3.

**מה בונים**
- מסך עם 3 לשוניות; badge מונה על «התראות» = מספר `readAt == null`.
- «סמן הכל נקרא» / «נקה ישנים» (ניקוי = מחיקה רכה מהמרכז — לא אוטומטי בזמן קריאה).
- כניסה: תפריט / dock «שירות».
- Nudges קיימים → לשונית התראות.

**Done when**
- ברור: איפה לטפל / איפה היסטוריה / איפה שליטה.
- read/unread עובד; פריטים נשארים אחרי סימון נקרא.
- מסך הגדרות כולל UI ל־OS (גם אם המימוש ב־E עדיין stub).

### שלב E — התראות מערכת באנדרואיד (טלפון עצמו)

> מסומן **E** (אחרי C) כדי לא לשבור את סדר A→B→C.  
> אפשר להתחיל הכנה טכנית במקביל ל־C (הרשאות, plugin), אבל **הפעלה למשתמש** רק אחרי שיש סכמה + העדפות במרכז.

#### E0 — מושגים (חובה להבין לפני מימוש)

1. **Local Notification**  
   נוצרת במכשיר ע״י האפליקציה (או בזמן שהיא פעילה/ברקע עם scheduler).  
   מתאים ל: Nudge מקומי, תזכורת «רק כשחשוב», סיכום שבועי מחושב באפליקציה, התראה מיד אחרי אירוע שכבר הגיע ל־WebView.  
   **לא דורש** שרת Push.  
   Plugin מומלץ: `@capacitor/local-notifications`.

2. **Push Notification (FCM)**  
   השרת שולח דרך Firebase Cloud Messaging → מגש אנדרואיד.  
   מתאים ל: התראה כשהאפליקציה סגורה לגמרי והאירוע נוצר בשרת (למשל נודג׳ שחושב ב־cron).  
   דורש: פרויקט Firebase, `google-services.json`, הרשאות, אחסון device token למשתמש, API שליחה.  
   Plugin מומלץ: `@capacitor/push-notifications` (+ שכבת שרת).

3. **המלצת גלים**  
   - **E1 — Local קודם** (פחות תשתית, מספיק לרוב תזכורות רועי ולסיכום שבועי).  
   - **E2 — Push** כשיש צורך אמיתי בהתראה מהשרת כשהאפליקציה מתה.

#### E1 — Local Notifications (מימוש מפורט)

**תלויות / פרויקט**
- הוספת `@capacitor/local-notifications` ל־`apps/mobile`.
- `npx cap sync android`.
- AndroidManifest: הרשאת `POST_NOTIFICATIONS` (API 33+); בדיקת runtime permission.
- יצירת **Notification Channels** (חובה באנדרואיד 8+), למשל:
  - `mt_important` — חשוב / סיכון (חשיבות HIGH)
  - `mt_nudge` — תזכורות רועי (DEFAULT)
  - `mt_digest` — סיכום שבועי (DEFAULT / LOW)
  - **לא** יוצרים ערוץ ל־SUCCESS שגרתי (כדי שלא יזלוג בטעות)

**זרימת הפעלה**
1. משתמש מדליק בהגדרות «התראת מערכת באנדרואיד».
2. האפליקציה מבקשת הרשאת התראות (אם עדיין לא).
3. אם נדחה — ההגדרה נשארת OFF + הסבר קצר + קישור להגדרות מערכת.
4. כשנוצר `NotificationEvent` עם `osEligible` ועבר את מטריצת ההעדפות → קריאה ל־LocalNotifications.schedule / מיידי.
5. לחיצה על ההתראה → deep link ל־`actionUrl` (למשל `/app/roey`) דרך App URL / Capacitor listener.
6. במקביל תמיד נשמר/מתעדכן פריט במרכז (read/unread) — ה־OS לא מחליף את המרכז.

**מתי שולחים Local (כללים מומלצים למוצר)**
- האפליקציה ב־foreground: בדרך כלל **רק Toast + Center**; OS אופציונלי ורק ל־IMPORTANT (כדי לא להציף).
- האפליקציה ב־background: OS לפי העדפות (NUDGE/IMPORTANT/DIGEST).
- SUCCESS של שמירת הוצאה: **לעולם לא ל־OS** כברירת מחדל (אפילו אם Toast דלוק).

**Done when (E1)**
- אפשר להדליק/לכבות OS מההגדרות.
- אחרי Nudge/IMPORTANT (בסימולציה) מופיעה התראה במגש האמולטור/מכשיר.
- לחיצה פותחת את המסך הנכון.
- בלי הרשאה — אין קריסה; יש מצב מוסבר בהגדרות.
- אין התראות OS להצלחות שגרתיות.

#### E2 — Push / FCM (המשך מפורט)

**מתי צריך**
- נודג׳ים שמיוצרים בשרת כשאין סשן פתוח באפליקציה.
- התראות אמיתיות «מהענן» למשתמש שלא פתח את האפליקציה ימים.

**מה בונים**
- Firebase project + `google-services.json` ב־Android.
- רישום `deviceToken` למשתמש (טבלה `UserDevice`).
- Endpoint שרת ששולח לפי אותה סכמה (`kind`, `titleHe`, `bodyHe`, `actionUrl`) ורק אם:
  - העדפת OS כללית דלוקה,
  - ה־kind מורשה במטריצה,
  - `notificationMode != OFF`.
- קישור Push → יצירת/עדכון `NotificationEvent` ב־DB כדי שיופיע גם במרכז כ־unread.

**Done when (E2)**
- שליחת test push מהשרת מגיעה למכשיר ונסגרת למרכז.
- כיבוי בהגדרות האפליקציה +/או הסרת הרשאת מערכת עוצרים שליחה (או לפחות מציגים בלי crash).

## 5. לשונית הגדרות — שליטה מפורטת (מה יתריע ואיפה)

כל ההעדפות חלות על **אותה סכמה**. ה־UI במרכז שירות → **הגדרות**.

### 5.1 עוצמת התראות (קיים / מורחב מ־`notificationMode`)

| ערך | משמעות במוצר | השפעה על מרכז | השפעה על OS |
|-----|----------------|---------------|-------------|
| `IMPORTANT_ONLY` (מומלץ) | רק סיכונים ותזכורות מהותיות | NUDGE/IMPORTANT בלשונית התראות | רק אלה (אם OS דלוק) |
| `WEEKLY` | פחות מיידי; סיכום שבועי | digest בעדכונים/התראות | Local מתוזמן לסיכום |
| `OFF` | בלי נודג׳ים יזומים | בלי NUDGE חדשים | בלי OS לנודג׳ים; Toast להצלחות משתמש עדיין אפשרי |

### 5.2 מתגים — «מה קורה באפליקציה»

| מתג | ברירת מחדל | התנהגות |
|-----|------------|---------|
| Toast מיידי במסך | ON | אישור קצר אחרי פעולה; נעלם; לא מוחק רשומת מרכז |
| שמירת הצלחות בעדכונים | ON | SUCCESS נשמר בלשונית עדכונים |
| תזכורות רועי במרכז | ON | NUDGE בלשונית התראות (read/unread) |

### 5.3 בלוק — «התראת מערכת באנדרואיד» (חדש, מפורט)

**מתג ראשי:** `osNotificationsEnabled`  
- OFF (ברירת מחדל עד שהמשתמש מדליק + מאשר הרשאה).  
- ON → מבקשים הרשאה; יוצרים channels; מאפשרים את תת־המתגים.

**תת־מתגים (פעילים רק כשהראשי ON + יש הרשאה):**

| מפתח העדפה | תווית UI (עברית) | ברירת מחדל כש־OS ON | מה מגיע למגש הטלפון |
|------------|------------------|---------------------|----------------------|
| `os.important` | סיכונים והתראות חשובות | ON | `IMPORTANT` |
| `os.nudge` | תזכורות רועי | ON אם mode≠OFF | `NUDGE` |
| `os.weeklyDigest` | סיכום שבועי | ON רק אם mode=WEEKLY | digest מתוזמן |
| `os.actionErrors` | שגיאות שדורשות טיפול | OFF | `ERROR` עם `osEligible` |
| `os.success` | אישורי הצלחה (שמירות וכו׳) | **OFF נעול/מוסתר** או OFF חזק | לא מומלץ; רק אם נפתח במפורש בניסוי |

**מצבי UI בהגדרות**
1. OS OFF — תת־מתגים אפורים + הסבר: «הפעילו כדי לקבל התראות גם כשהאפליקציה סגורה».
2. OS ON, אין הרשאת מערכת — באנר שירותי: «ההרשאה כבויה במכשיר» + כפתור «לפתיחת הגדרות אנדרואיד».
3. OS ON + הרשאה — תת־מתגים פעילים; תצוגת ערוצים (channels) לקריאה בלבד («חשיבות גבוהה / רגילה»).
4. מצב דפדפן / בלי Capacitor — המתג הראשי מוסתר או disabled עם: «זמין באפליקציית אנדרואיד».

**נוסחת החלטה לשליחה ל־OS (פסאודו־קוד)**

```text
if (!osNotificationsEnabled) return;
if (!systemPermissionGranted) return;
if (!event.osEligible) return;
if (notificationMode == OFF && event.kind in [NUDGE, IMPORTANT_DIGEST]) return;
if (event.kind == IMPORTANT && !os.important) return;
if (event.kind == NUDGE && !os.nudge) return;
if (event.kind == ERROR && !os.actionErrors) return;
if (event.kind == SUCCESS && !os.success) return;
deliverToAndroid(event);
```

### 5.4 הפרדה ברורה למשתמש (טקסט עזר בהגדרות)

- **במסך האפליקציה:** Toast קצר + מרכז שירות (תמיד זמין כשהאפליקציה פתוחה).  
- **בטלפון עצמו:** מגש אנדרואיד — רק מה שסומן בבלוק OS, ורק אחרי הרשאה.  
- **סימון נקרא במרכז לא מציית למחיקת התראת OS** (אפשר בעתיד לבטל גם את ה־OS notification לפי `notificationId`; לא חובה ב־E1).

## 10. בדיקות — צ׳ק־ליסט מפורט

### אחרי A
- אובייקט סכמה לכל kind; `readAt` null בהתחלה; `osEligible` לפי הטבלה.

### אחרי B
1. רועי → סשן חדש → toast; הצ׳אט פנוי  
2. מעבר מסכים → אין באנר דביק ישן  
3. שמירת הוצאה → toast  

### אחרי C
1. פריט חשוב ב«התראות» עם תגית חדש  
2. «סמן הכל נקרא» → עובר ל«נקראו», **לא נמחק**  
3. הצלחה ב«עדכונים» לפי יום  
4. הגדרות: מתגי Toast / שמירה / OS (UI)  

### אחרי E1 (אמולטור/מכשיר אנדרואיד)
1. OS OFF → אין התראת מגש  
2. OS ON בלי הרשאה → בקשה / הסבר  
3. OS ON + important ON → סימולציית IMPORTANT מופיעה במגש  
4. os.nudge OFF → NUDGE לא במגש (עדיין במרכז)  
5. שמירת הוצאה → Toast כן, מגש לא  
6. הקשה על מגש → ניווט לרועי/יעדים  
7. Background: האפליקציה ברקע עדיין מקבלת Local לפי הכללים  

### ביקורת חוזרת (D)
- ממצאים + חומרה + תיקון + re-test + עדכון יומן

## 12. סיכום

1. **סכמה אחת** לכל הערוצים (Toast, מרכז, אנדרואיד).  
2. **Toast** = מיידי ונעלם; **מרכז** = נשאר עם חדש/נקרא.  
3. **מרכז שירות** = התראות / עדכונים / הגדרות.  
4. **אנדרואיד** = ערוץ `OS` עם מתג ראשי + תת־מתגים לכל סוג; Local קודם, Push אחר כך.  
5. בלי הרשאת טלפון — האפליקציה עדיין מלאה; המגש פשוט כבוי.
