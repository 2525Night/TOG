## 1. תפקיד האשראי

הכרטיס הוא **ערוץ תשלום**, לא קטגוריה ולא «חוב» בכותרת.

| מה | משמעות | מה נספר מתי |
|---|---|---|
| קנייה בכרטיס | הוצאה אמיתית | בחודש הקנייה / תשלום החודש בפריסה |
| פריסת תשלומים | התחייבות עתידית | «שמור לתשלומים» עד שהחודש מגיע |
| סילוק כרטיס | העברה לעו״ש | לא הוצאה |

בלי כפל ספירה: רק תשלום החודש בהוצאות; היתר התחייבות.

---

## 2. שלושה סוגי חיוב (מודל)

### א) חד־פעמי בכרטיס
סכום מלא → `CARD_PURCHASE` + יתרת מחזור.

### ב) פריסת תשלומים
- בשמירה: תשלום 1/N בהוצאות + `InstallmentPlan` ליתרה.
- כל חודש רלוונטי: תנועת `CARD_PURCHASE` לתשלום הבא (`chargedCount++`).
- רטרו / פריסה שכבר רצה: «ייבוא פריסה» עם `chargedCount` — בלי כפל הוצאות ישנות.

### ג) הוראת קבע באשראי *(גל 2)*
התחייבות חוזרת (`BudgetCommitment`) עם `payVia = CREDIT_CARD` + כרטיס.
- מופיעה בהוצאות קבועות כמו כל קבועה.
- ברישום חודשי: `CARD_PURCHASE` חד־פעמי (לא פריסה) — הוצאה + יתרת מחזור; העו״ש לא זז עד סילוק.
- לא מערבבים עם «קבועה מהעו״ש» (`payVia = ACCOUNT`).

## 3. שני פתחים — אותה פעולה

| מקום | זרימה |
|---|---|
| תנועות | הוצאה → איך שולם: כרטיס → כרטיס → חד־פעמי / תשלומים → שמירה |
| אשראי → כרטיס | «הוסף חיוב» → אותו API |

אחרי שמירה: משוב מפורש (סכום החודש + התחייבות שנותרה) + קישור לכרטיס כשייך.

---

## 4. גל 1 — דרישות (מאושר)

1. מחיקת תנועה/פריסה מסנכרנת יתרה והתחייבות (ללא פריסה יתומה).
2. רישום תשלומי אשראי לחודש נבחר (לולאת פריסה) — בלי לייצר הוצאות לחודשים שדולגו (catch-up מונה בלבד).
3. משוב שמירה בתנועות ובמסך כרטיס לפריסה.
4. בהירות: «הוצאות במחזור» = חודש נבחר; התחייבות תשלומים = נותר.

**מחוץ לגל 1:** הוראת קבע באשראי *(→ גל 2)*; עריכת סכום עסקת פריסה (מחיקה + הזנה מחדש).

---

## 4ב. גל 2 — דרישות (מאושר)

1. שדות על התחייבות: `payVia` (`ACCOUNT` | `CREDIT_CARD`) + `creditCardId` כשייך.
2. «שמור טיוטה כקבועה» עם «איך שולם: כרטיס» שומר הוראת קבע באשראי.
3. רישום פתוחות / מילוי צ׳יפ: כרטיס → `CARD_PURCHASE`; חשבון → תנועה רגילה.
4. תווית ברורה על צ׳יפ («כרטיס») בלי לבלבל עם פריסת תשלומים.
5. MonthFacts: התאמת actual גם ל־`CARD_PURCHASE`; בלי כפל ספירה.

**מחוץ לגל 2:** שינוי `payVia` אחרי יצירה (מחיקה + יצירה מחדש); ייבוא אוטומטי מהצהרת כרטיס.

## 5. רטרו וחודשים

| מצב | התנהגות |
|---|---|
| חודש חדש + פריסה פעילה | `charge-due` יוצר תשלום לחודש הנבחר אם מגיע לפי לוח |
| דילוג חודשים באפליקציה | מקדמים `chargedCount` בלי תנועות ישנות, ואז רושמים את החודש הנוכחי |
| תאריך קנייה בעבר | הוצאה בחודש התאריך; לא מופיעה ב«הוצאות במחזור» של חודש אחר |
| פריסה מחוץ לאפליקציה | ייבוא פריסה עם כבר־חויבו |
